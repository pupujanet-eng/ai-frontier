# AI Frontier · pupu 的 AI 日报

每日中文 AI 资讯、跨来源趋势专题与分层知识图谱。

线上站点：https://pupujanet-eng.github.io/ai-frontier/

## 阅读

- 趋势专题：事件背景 → 机制 → 不同来源的观点 → 证据边界 → 后续观察。
- 知识图谱：模型与能力、算力与数据、Agent 与编排、产品与体验、商业与市场、评估与治理。点击节点查看概念关系和本期关联材料；连线是编辑框架，不是自动推定的事实因果。
- 保留全球热榜、PM 关联、GitHub、访谈与观点、行业、国内、研究栏目。
- `/` 搜索去重后的全部资讯（含 GitHub）与专题；`Esc` 清除；`j/k` 或方向上下键逐条阅读；`PageDown/PageUp` 或空格/Shift+空格翻屏；`1–7` 原栏目，`8` 专题，`9` 图谱；`?` 帮助。输入框、中文输入法和原生按钮不抢键。

## 生成流程

1. 32 个可配置来源（RSS 与官方新闻页），覆盖官方博客、论文、专业媒体、中文媒体、独立作者与长访谈。新闻回看 14 天，访谈回看 30 天。不可用、没有近期条目、缺失日期分别记录，不把抓取时间当发布日期。
2. 按发布者轮询选材，一手来源在每轮优先；最多 64 篇、每源最多 6 篇。对允许名单内的短 RSS 内容补抓公开正文，不绕过付费墙。GitHub 使用独立额度。
3. 使用 API 层 JSON Schema 约束输出，并用稳定文章 ID 分类和深读。与 AI 无关或材料过少的内容淘汰；保留发布时间、来源类型、影响与限制。输出乱序不会使摘要与链接串位；缺项、重复 ID、截断 JSON 均重试后失败退出。分类和专题都保留业务校验；已验证分类按输入内容和模型配置缓存，失败重跑时可复用，避免重复付费。
4. 编辑模型先规划 2–3 个跨来源选题，单一发布者选题会独立检索其他发布者的相关证据，仍不足则弃题，不牵连其他选题。再分别生成导语与四节正文，每节独立校验、重试和缓存。每节保留来源 ID 和事实/分析/不确定性标签，拒绝未知引用或单域名专题。多个域名不等于独立验证；访谈嘉宾观点也不是产品内部实现的证据。
5. 热榜限近 7 天且有充分材料的条目；旧闻可以作为专题背景。本期洞见拆成选重点、逐点解释、总判断三个阶段；每个单元最多修复 3 次，修复时携带上版正文和具体错误。只有通过校验的内容才缓存复用。
6. 发布硬门槛：同一天的本期洞见（2–3 个重点、逐字匹配的高亮、至少两个发布者）和至少 1 篇本期趋势专题（四节完整正文、跨来源引用、近 72 小时新材料、至少两个后续观察指标）必须同时存在。旧专题、占位文字和日期不符的内容都不能凑数。生成结束和部署之前分别校验，完整校验后原子替换 `latest.json`。生成失败不发布，保留线上上一期。GitHub Actions 缓存近期日报与上榜历史，另保留 90 天数据 artifact；缓存可能被 GitHub 清理，不能视为永久存储。

编辑精选保存在 `data/briefings/*.json`，有核对日期，与近 14 天已刊专题一起放入默认收起的「背景深读」，不计入本期更新。Dots 示例将官方产品事实、Noam Brown 访谈观点和编辑推断分开，后续自动专题不依赖固定关键词。

来源清单与窗口见 `scripts/fetch-feeds.ts`；不是对整个互联网的穷尽搜索。模型可能仍有事实误读，重要决策请回到引用原文。来源覆盖面板公开当前采集状况。

## 模型费用与熔断

按北京时间自然日共享三项阈值，GitHub Actions 仓库 Variables 或本地环境变量可配置：

| 变量 | 默认值 | 行为 |
| --- | --- | --- |
| `DAILY_MODEL_BUDGET_USD` | `5` | 下一次请求的预留费用超过当日剩余额度时停止 |
| `DAILY_MODEL_MAX_CALLS` | `80` | 最多发起 80 次生成请求，包括失败和修复 |
| `DAILY_MODEL_MAX_FAILURES` | `12` | 累计 12 次内容校验失败后停止，避免反复返工 |

每次生成先调用 Count Tokens，再按输入估算加 10% 与 1,024 token 余量、最大输出 token 预留费用，并在发出付费请求之前原子保存账本。返回后立即按实际 `usage` 结算；未通过内容校验或截断的输出同样入账。账本记录模型、栏目单元、输入/输出及缓存 token、请求 ID、停止原因、估算美元费用，不含 API key 或资料正文。日志输出每次费用与当天累计费用。

SDK 自动重试已关闭。400/401/402/403/404 等非暂时性接口错误立即熔断至下一个北京时间自然日；429、408/409、5xx、网络错误和超时立即结束当前生成，至少冷却 30 分钟后才允许后续定时任务尝试，不在进程内等待重试。没有拿到 usage 的请求保留全部预留费用。熔断异常贯穿分类、单篇兜底、本期洞见和专题循环，不能被当作普通内容错误吞掉。

生产账本独立于可清理的生成缓存，通过 `model-budget-日期-run_id-attempt` Actions artifact 保留 90 天；后续定时、push 与手动重跑恢复同一天最新账本。工作流串行执行；发现当天此前启动过生成却没有可读账本（包括上传失败、取消任务、旧版本无账本），拒绝重新授予预算。首次上线当天若已经运行过旧生成流程，会等到下一北京时间自然日再开始付费生成。恢复或保存失败也停止；不能通过清缓存、再次点击运行来重置额度。代码升级的 `[deploy cached]` 部署不触发模型调用。

预算按 Haiku 4.5 输入/输出 $1/$5、Sonnet 4.6 $3/$15 每百万 token 的标准价格估算；具体见 [官方价格](https://platform.claude.com/docs/en/about-claude/pricing)。只允许代码价格表中已核对的模型，切换其他模型需同时维护价格。Count Tokens 是估算，供应商价格、账单调整和未知超时用量意味着此控制不是供应商侧绝对账单限额。该预算只约束本流水线，不覆盖其他程序共用 API key 的消费。并行本地进程不受 Actions 串行锁保护，请勿同时运行本地生成。

达到阈值或发生故障时退出失败，不覆盖线上上一期；本期洞见和至少一个完整趋势专题的发布门槛保持不变。排查时先查看 `[model-usage]` 日志和当天 `model-budget` artifact，不要删除账本或放宽内容校验来强行发布。金额阈值不代表保证每天能在该金额内完成日报。

## 部署

GitHub Settings → Secrets and variables → Actions 配置 `ANTHROPIC_API_KEY`。Pages Source 选择 GitHub Actions。

推送 `main`、手动执行或北京时间每日 08:17 首次触发，11:17、14:17、20:17 自动补跑。当日已完整则不再调用模型；尚不完整则复用已通过校验的生成缓存继续修复。GitHub 调度可能延迟，外部服务持续故障时保留上一期及其真实日期，不伪造当天内容。部署使用 `NEXT_PUBLIC_BASE_PATH=/ai-frontier`；本地默认根路径。`skip_generate` 可用最近缓存数据重建界面，页面始终显示实际日报日期。

生产发布前运行测试、Lint、TypeScript 与静态构建。日志及数据 artifact 可用于排查来源故障、生成错误和证据质量；API key 不写入站点或日志。


仅修复界面或展示规则时，可手动运行工作流并勾选 `skip_generate`；也可在提交说明中加入 `[deploy cached]`，使用最近保存的日报重新构建部署，避免重复调用模型。缓存重建同样必须通过完整性校验；旧的缺栏目缓存不能绕过门槛。单个专题失败但另有完整专题时可发布，所有专题失败或洞见失败则整个工作流失败，保留线上上一期。失败原因保存为 editorial-diagnostics artifact；生成缓存会在失败后保存，供自动补跑复用。

专题状态包含选题数、刊出数和失败原因，某节失败不会重写其他已完成章节。页首洞见直接依据资讯独立生成，完整单元分别缓存。界面统一使用本机中文字体栈（无外部字体下载）、15/13/12/11px 标题/正文/说明/元信息、共用正文 Markdown 渲染器和中性标签；只有核心洞见精选关键词使用浅色高亮。

## v0.2.0 · 个人阅读与可恢复交付

- `0` 跳转「我的阅读」。按角色、关注方向和 5/10/20 分钟筛选 3/5/8 条资讯；规则在浏览器运行，无额外模型调用。
- 资讯与专题支持收藏、已读、意向标签、追加批注；专题支持留下判断，满七天后在「七天后的我」回看，保留原判断与修正记录。
- 知识图谱显示跨期已读和收藏数量。每期最多选择三条制作 PNG 分享卡，支持下载图片、复制图片或文字。私人批注默认不加入分享。
- 日期切换读取同站静态 JSON，展示最多 90 期通过完整性校验的日报；与上一完整期对照新增、持续收录及原文摘录更新。仅重写中文摘要不算新闻更新。历史日期和今日未更新状态明确显示。

### 个人资料的存储与迁移

个人资料使用 `ai-frontier.reader.v1` 存储在当前站点、当前浏览器的 localStorage，写入前保存上一完整副本。刷新与站点代码升级保留数据，同一浏览器多个页面按字段修改时间合并；笔记和判断使用唯一 ID 追加保留。

跨设备使用「备份与设备迁移」导出 JSON，再导入另一设备；导入先校验结构、版本、链接、大小和引用完整性，展示数量后由读者确认合并。限制为 2 MB、2,000 条资料、每条 100 条批注及 100 次判断、730 期分享选择。文件不可识别时保持现有数据；存储被禁用或空间不足时明确提示，并允许导出本页修改。损坏原件暂停覆盖，恢复需要明确操作。

GitHub Pages 提供静态内容，不提供用户账户和跨设备自动同步。个人偏好与批注不上传到仓库、Actions 或模型服务。浏览器清理、换域名、隐私窗口关闭可能导致本地记录不可用；长期使用请定期导出备份。备份含私人文字，应自行妥善保存。复制图片受浏览器权限与兼容性影响，可使用 PNG 下载；复制文字失败时提供 TXT 下载。

### 生成与部署恢复

分类输出按输入文章 ID 设置必填对象，避免数组合法但漏项或返回空数组；业务层继续拒绝缺失、未知或错配 ID。结构使用 [Claude 官方文档支持的 JSON Schema 子集](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)。分类增加逐篇检查点：同一文章、正文和模型配置相同即可跨批次复用，通过校验的排除结果也保存。本期洞见无法完成时立即停止后续专题付费生成。完整性门槛继续要求本期洞见与至少一个完整专题同时成立。

部署恢复先校验 Actions 缓存；缓存缺失或不完整时尝试最近五份未过期的日报数据 artifact。ZIP 只提取允许的数据文件，限制大小并重新校验，全部失败时停止部署，保留当前线上页面。构建仅将通过校验的日报输出到 `public/editions`，个人资料、模型账本、API key 均不在静态目录。

更换 Claude key：仓库 **Settings → Secrets and variables → Actions → Repository secrets → ANTHROPIC_API_KEY → Edit**，由管理员直接粘贴并保存。随后在 **Actions → Daily Digest + Deploy → Run workflow** 执行生成，关闭 `skip_generate`；若当天因接口错误已经熔断，可开启 `resume_model_service`。该选项只解除接口故障熔断，保留当日费用、请求次数、校验失败次数及未结算预留，费用阈值仍生效。未经修复的 401 再次请求仍会立即停止。

### 历史版本与验收

升级前源码归档为 `archive/pre-personalization-2026-11-24`；新版标记为 `v0.2.0`。Git 历史保留原实现。需要回退时，从历史标签检查差异，通过新的回退提交发布，避免强制重写 main。页面个人数据版本独立为 v1，后续升级需保持兼容或提供显式迁移。

发布检查：`npm test`、`npm run lint`、`npx tsc --noEmit`、`npm run build`。验证带 `/ai-frontier` 子路径的静态部署、刷新后的保存、备份合并、分享导出以及窄屏排版。自动测试覆盖损坏数据、空间不足、跨页面修改、七天回看、原文变更识别、逐篇缓存、归档提取和熔断恢复。
